## 2024-05-17 - Throttling Pointer Events and Synchronous Context Extraction

**Learning:** When applying `requestAnimationFrame` throttles to event listeners that fire rapidly (like `pointermove`), you cannot pass the synthetic event object (e.g., the standard DOM event) directly into the asynchronous callback if the original handler expects to read properties from it. The event object loses context, and its properties (like `clientX` and `clientY`) might not be accurate or accessible by the time the frame executes. Furthermore, for elements that continuously track the cursor and whose relative positions change constantly (like a runaway button), caching `getBoundingClientRect` isn't viable.
**Action:** When wrapping vanilla DOM event handlers in asynchronous callbacks like `requestAnimationFrame`, extract necessary properties synchronously beforehand (e.g., `const clientX = event.clientX;`) and refactor the inner function to accept those primitive coordinates directly rather than a full native event object. This mitigates layout thrashing from recalculating `getBoundingClientRect` on rapid events without causing context loss.
