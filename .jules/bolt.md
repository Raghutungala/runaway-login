## 2024-03-24 - Throttling rapid DOM events with `requestAnimationFrame`
**Learning:** Rapid events like `pointermove` cause layout thrashing when triggering operations that read element positions (e.g., `getBoundingClientRect`). Wrapping the logic in `requestAnimationFrame` fixes layout thrashing, but passing the original `event` object into the async callback can lead to context loss (like `currentTarget` becoming null). Also, you must update primitive coordinates outside the throttle check on every event tick, otherwise final mouse positions get discarded.
**Action:** When throttling rapid events with `requestAnimationFrame`, extract necessary primitive values (like `clientX`, `clientY`) from the event object synchronously and store them in outer scoped variables. Update these variables on every event invocation outside the throttle condition, and pass the primitives to the logic inside the animation frame callback.
