## 2024-05-24 - Throttling pointermove events
**Learning:** For elements that aggressively track cursor position (e.g., the runaway button in this project), caching `getBoundingClientRect` is often unviable because relative positions change constantly. Mitigate layout thrashing by throttling rapid events like `pointermove` using `requestAnimationFrame`. When throttling rapid pointer events (like `pointermove`) using `requestAnimationFrame`, always update state tracking variables with the latest coordinate values (`clientX`, `clientY`) on every event invocation outside the throttle condition. This ensures the final mouse position is not discarded when the user stops moving the mouse abruptly before the next animation frame renders. Also, when wrapping vanilla DOM event handlers in asynchronous callbacks like `requestAnimationFrame`, extract necessary properties (e.g., `clientX`, `clientY`) synchronously beforehand. The event object may lose context (e.g., `currentTarget` evaluating to null) by the time the asynchronous callback executes.
**Action:** Use requestAnimationFrame to throttle `pointermove` handlers and store event properties needed by the handler beforehand to prevent state from going out of sync.
