## 2024-05-24 - Throttling pointermove and avoiding event context loss
**Learning:** For elements that aggressively track cursor position and perform layout-thrashing tasks (like reading `getBoundingClientRect`), throttling `pointermove` with `requestAnimationFrame` is crucial for performance. However, if a function takes an `Event` object, running it asynchronously inside `requestAnimationFrame` can lead to errors because the event's context may change or its properties may be cleared by the time the frame runs. Furthermore, if you throttle, you must still capture the latest `clientX` and `clientY` synchronously *outside* the throttle check, or else you might drop the final position when the mouse stops moving.
**Action:** When wrapping vanilla DOM event handlers in asynchronous callbacks like `requestAnimationFrame`, extract necessary primitive properties (e.g., `clientX`, `clientY`) synchronously beforehand. Update these tracking variables on every event invocation outside the throttle condition, and pass the primitives to the inner function.
