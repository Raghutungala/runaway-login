## 2024-10-24 - Throttling High-Frequency Pointer Events
**Learning:** In this runaway button implementation, the `pointermove` event fires at the hardware polling rate (up to 1000Hz). When the cursor is outside the activation radius, the condition `distance > 105` causes an early return without updating `lastEscape`. This means that `now - lastEscape < 120` doesn't protect against layout thrashing, and `getBoundingClientRect` is called on the `zone` and `button` on *every single* sub-pixel pointer movement, causing excessive synchronous layout calculations that can block the main thread.
**Action:** Always throttle high-frequency input events (like `pointermove`) using `requestAnimationFrame` before reading layout properties to decouple the event rate from the browser's render rate, ensuring layout calculations occur at most once per frame.
