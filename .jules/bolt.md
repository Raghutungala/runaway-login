## 2024-10-24 - Throttling Pointer Events for Aggressively Tracking Elements
**Learning:** For elements that aggressively track cursor position (e.g., the runaway button in this project), computing `getBoundingClientRect` on every `pointermove` can cause layout thrashing. Caching the rects is often unviable because relative positions change constantly.
**Action:** Throttled rapid events like `pointermove` using `requestAnimationFrame`. Crucially, when wrapping vanilla DOM event handlers in asynchronous callbacks like `requestAnimationFrame`, extract necessary properties (e.g., `clientX`, `clientY`) synchronously beforehand. The event object may lose context (e.g., `currentTarget` evaluating to null) by the time the asynchronous callback executes. Avoid passing a full synthetic event object down if the inner function expects native event semantics; instead, refactor the inner function to accept just the needed properties.
